# Marquee Events

Event management app — FastAPI backend, React/TypeScript frontend.

```
backend/    Event Management API — uv, ruff, mypy --strict, pytest
frontend/   Marquee Events UI — Vite, React 19, oxlint, Prettier, Vitest,
            TanStack Query, Tailwind v4, shadcn/ui
```

## Prerequisites

You need two things installed. Everything else is handled for you.

| Tool | Install | Notes |
| --- | --- | --- |
| [uv](https://docs.astral.sh/uv/) | `brew install uv` or `curl -LsSf https://astral.sh/uv/install.sh \| sh` | Downloads and pins Python 3.14 itself — you do not need Python installed. |
| [Node.js](https://nodejs.org) 22.12+ | `brew install node`, or `nvm use` to pick up `frontend/.nvmrc` | |

Check them:

```bash
uv --version
node --version
```

## Setup

```bash
git clone https://github.com/SKainec/origin-digital-takehome.git
cd origin-digital-takehome
make install
```

`make install` does three things: installs backend dependencies with `uv sync`
(fetching Python 3.14 on first run), installs frontend dependencies with
`npm install`, and installs the git pre-commit hooks.

Confirm it worked:

```bash
make ci
```

That runs the full pipeline — lint, type check, both test suites, and a
production build. If it passes, your environment is correct.

## Running the app

```bash
make dev
```

- UI — <http://localhost:5173>
- API — <http://127.0.0.1:8000>
- API docs (Swagger) — <http://127.0.0.1:8000/docs>

Vite proxies `/api` to the backend, so the browser sees a single origin and
there is no CORS setup to fight in development. To run just one side, use
`make dev-backend` or `make dev-frontend`.

## Configuration

**Optional** — every setting has a working default, so the app runs with no
`.env` at all. To override:

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

Backend settings are prefixed with `APP_` (see `backend/src/app/config.py`).
Unrecognised keys are ignored, so a shared `.env` can safely hold values for
other tools. List values are parsed as JSON.

| Variable | Default | Purpose |
| --- | --- | --- |
| `APP_APP_NAME` | `Event Management API` | Shown in the OpenAPI docs and `/api/health`. |
| `APP_DEBUG` | `false` | |
| `APP_CORS_ORIGINS` | `["http://localhost:5173"]` | JSON array of allowed origins. |
| `VITE_API_URL` | *(empty)* | Points a built frontend at the API. Leave empty in dev — the Vite proxy handles it. |

## Pre-commit hooks

`make install` registers them, so they run automatically on `git commit`:
whitespace and merge-conflict checks, private-key detection, `ruff` check and
format on the backend, `mypy --strict`, and Prettier plus oxlint on the frontend.

```bash
# run every hook against every file, without committing
uv run --project backend pre-commit run --all-files

# re-register after changing .pre-commit-config.yaml
uv run --project backend pre-commit install

# bypass in an emergency (CI will still catch it)
git commit --no-verify
```

`ruff` autofixes in place, so if a commit is blocked by formatting, re-stage the
modified files and commit again.

## Design decisions

**One repository, two applications.** The brief allows separate repos; a single
one keeps the API contract and its consumer reviewable in one diff, and lets a
single `make` command run and check both sides. `backend/` and `frontend/` stay
independently buildable and deployable — nothing is shared at the code level.

**Tailwind and shadcn/ui for the interface.** shadcn gives a good-looking,
accessible baseline out of the box — Radix primitives underneath, so keyboard
and screen-reader behaviour is handled — which means time goes into the
functionality rather than into styling. Tailwind v4 is its prerequisite, and its
theme tokens cover light and dark mode.

**Types as the contract at both ends.** Pydantic models are the single source of
truth on the backend — they validate requests and generate the OpenAPI schema,
so the docs cannot drift from the code. On the frontend, `src/api/` maps the
API's `snake_case` to `camelCase` at one boundary, keeping the rest of the app
in idiomatic TypeScript.

**Times are stored as UTC instants.** `starts_at` must be timezone-aware and is
serialized as ISO 8601 with an offset, because JavaScript parses an offsetless
datetime string as *local* time — a naive value would silently shift by the
viewer's UTC offset on the way to the browser. The client converts back with
`toISOString()` on submit and formats with `toLocaleString` for display, so no
date library is needed: there is no arithmetic, only parse and format.

The tradeoff is that an instant means "19:00 UTC", not "19:00 at the venue". If
an event's local time needed to survive a DST shift, the right model would be
wall-clock time plus an IANA zone id rather than an instant. That is beyond this
exercise, but it is a real distinction rather than an oversight.

**TanStack Query rather than `useEffect` fetching.** Caching, retries, request
cancellation, and loading/error state come from one dependency instead of being
re-implemented, incorrectly, per component.

**A single `make` interface.** Both stacks have different runners; `make` gives
one vocabulary for both and keeps CI honest — `make ci` runs exactly what the
pipeline runs, so "works on my machine" is checkable in one command.

**Test-first.** Both suites run in CI on every push, with coverage on the
backend. Conventions are written down in [CLAUDE.md](./CLAUDE.md) rather than
left implicit.

## Tooling choices

| Concern | Choice | Why |
| --- | --- | --- |
| Python packaging | **uv** | Fast, lockfile-based, manages the interpreter itself. |
| Python format + lint | **ruff** | One tool in place of black, isort, and flake8. |
| Python typing | **mypy `--strict`** | Full annotation coverage, with the pydantic plugin. |
| Runtime validation | **pydantic v2** | Models double as the OpenAPI schema. |
| JS lint | **oxlint** | Rust-based, type-aware via tsgolint, now the Vite default. |
| JS format | **Prettier** | oxlint deliberately does not format. |
| Tests | **pytest** / **Vitest + RTL** | Backend reports coverage on every run. |
| Server state | **TanStack Query** | Caching, retries, and request cancellation for free. |
| UI | **Tailwind v4 + shadcn/ui** | Components are copied into the repo, so they are ours to own. |

## Continuous integration

`.github/workflows/ci.yml` runs the backend and frontend as parallel jobs on
every push and pull request: format check, lint, type check, tests, and — for
the frontend — a production build.

## Troubleshooting

**`uv: command not found`** — install it with the command in Prerequisites, then
restart your shell.

**Wrong Node version** — `nvm use` in `frontend/` picks up `.nvmrc`.

**Port already in use** — `make dev-backend` and `make dev-frontend` run the
sides separately so you can change one port without touching the other.

**Stale caches after dependency changes** — `make clean`, then `make install`.
